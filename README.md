# Анализ требований с использованием User Story

## О проекте

Проект посвящён анализу требований к информационной системе онлайн-записи в барбершоп.

В рамках проекта выполнено выявление потребностей пользователей и формирование требований в формате User Story для основных ролей системы:

- менеджер;
- клиент;
- мастер.

Для каждой пользовательской истории определены:
- потребность пользователя;
- описание ценности;
- критерии приемки (Acceptance Criteria);
- тестовые сценарии.

Также проведено обсуждение и согласование пользовательских историй с использованием подходов 3C и INVEST.

---

## Цель проекта

Научиться выявлять и документировать пользовательские потребности, формировать требования к системе и проверять их качество.

---

## Предметная область

Рассматривается информационная система онлайн-записи в барбершоп.

Система должна поддерживать основные процессы:

- запись клиентов на услуги;
- выбор мастера и времени посещения;
- управление расписанием мастеров;
- получение уведомлений о записи;
- анализ отзывов клиентов;
- получение отчетов о выполненных услугах.

---

## Роли пользователей

### Клиент

Основные потребности:

- выбрать услугу и мастера;
- записаться на удобное время;
- получать уведомления о предстоящем посещении.

---

### Мастер

Основные потребности:

- просматривать личное расписание;
- видеть записи клиентов;
- анализировать отзывы о своей работе.

---

### Менеджер

Основные потребности:

- управлять расписанием мастеров;
- контролировать актуальность записей;
- получать отчеты о выполненных услугах.

---

## Использованные подходы

### User Story

Пользовательские истории описывались по формату:

> Как [роль пользователя],  
> я хочу [действие],  
> чтобы [получить ценность].

---

### Acceptance Criteria

Для проверки выполнения требований использовалась структура:

- Given — предусловие;
- When — действие пользователя;
- Then — ожидаемый результат.

---

### Test Scenarios

Для отдельных пользовательских историй были разработаны тестовые сценарии:

- предусловия;
- действия пользователя;
- ожидаемый результат.

---

### INVEST

Пользовательские истории проверялись по принципам:

- Independent — независимость;
- Negotiable — возможность обсуждения;
- Valuable — наличие ценности;
- Estimable — возможность оценки;
- Small — компактность;
- Testable — тестируемость.
